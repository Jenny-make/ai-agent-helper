# Changelog

本文档记录项目阶段性进展、当前版本定位与后续版本计划。

---

## Unreleased

更新时间：2026-04-19

当前代码仍处于未发布开发阶段。`build.gradle` 当前版本号为 `0.0.1-SNAPSHOT`，阶段目标按 `0.1.0-SNAPSHOT` 收尾。

### 当前定位

**飞书客服问答 MVP / 可本地与飞书双入口验证的第一版客服基座**

项目已经从纯聊天 Demo 推进到“飞书文本消息闭环 + 会话记忆 + 第一版飞书知识同步 + RAG 检索回答”的可验证阶段，但距离生产可用仍缺少安全、运营和客服业务闭环。

### 已完成

- 增加多模型接入能力：
  - `DeepSeek`
  - `MiniMax`
  - `OpenAI-compatible`
- 增加 `app.ai.provider` 路由逻辑，支持 `auto` 模式。
- 增加 Spring AI 自动配置排除逻辑，避免未使用 provider 影响启动。
- 增加控制台问答入口：
  - 本地直接输入问题验证模型调用。
  - 支持 `/new`、`/history`、`/session`、`/help`。
  - 支持超时和错误打印。
- 增加会话记忆能力：
  - 最近轮次保留。
  - 历史摘要压缩。
  - 模糊追问消歧。
  - 简单事实回忆。
  - 配置 DataSource 后使用 JDBC 持久化。
- 增加活跃文档状态：
  - 根据 RAG 命中文档记录当前 session 的 active document。
  - 配置 DataSource 后可持久化。
  - 文档追问可按 `sourceToken` 等元数据过滤。
- 增加回答文本策略能力：
  - 语言跟随最新用户消息。
  - 上下文相关追问识别。
  - 语言切换重写。
  - prompt 泄漏 / 元响应 / 重复文本清洗。
  - 文档类问题无检索证据时保守回答。
- 增加可选 RAG 检索入口与配置项。
- 增加向量库健康检查接口：`GET /api/admin/health/vector`。
- 增加飞书基础消息闭环：
  - `url_verification`
  - `im.message.receive_v1` 文本消息解析
  - p2p 自动回复
  - 群聊 `@` 识别与消息清洗
  - 重复投递去重
  - 租户访问令牌获取与缓存
  - 调用飞书 Open API 回发文本消息
  - `/new` 清理当前会话记忆和活跃文档
- 增加飞书知识同步第一版：
  - 支持 `docx` token / 链接拉取纯文本。
  - 支持底层对象为 `docx` 的 `wiki` 页面。
  - 支持飞书文件夹递归展开 `docx`、嵌套文件夹和快捷方式。
  - 支持本地切片。
  - 支持写入 `VectorStore / Milvus`。
  - 支持本地状态文件记录上次 chunk ids，重复同步时先删旧 chunk 再写入。
  - 支持管理接口手动触发同步。
  - 支持启动时自动同步开关。
- 增加 Flyway migration：
  - `conversation_thread`
  - `conversation_message`
  - `active_document`
- 增加 MiniMax 运行配置模板与控制台 / 飞书调试说明。
- 增加单元测试，覆盖飞书消息过滤与去重、`/new`、会话记忆、知识同步、文档问答、语言与文本策略等核心路径。

### 当前限制

- 飞书仍未完成加密事件体解密与更严格的签名校验。
- 当前仅支持飞书文本消息，不支持图片、文件、卡片等消息类型。
- 飞书知识同步仍是第一版，不支持 PDF / DOC / PPT 等文件解析。
- `wiki` 仅支持单个 wiki 页面且底层对象必须是 `docx`，尚未支持完整 wiki 树同步。
- 尚未支持按飞书更新时间做定时增量同步。
- 知识同步状态目前存储在本地 JSON 文件，生产环境应迁移到数据库。
- RAG 入库依赖可用的 Spring AI embedding / Milvus 配置；没有对应 bean 时无法完成向量写入。
- 尚无转人工、工单、审计日志、限流、监控告警、多租户隔离等企业客服能力。
